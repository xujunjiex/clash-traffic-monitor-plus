# clash-traffic-monitor 使用报告（部署于 2026-10-24 凌晨）

## 一句话

打开浏览器访问 **http://127.0.0.1:18080** 即可看到 Clash 流量按域名/节点/规则的实时与历史统计。

## 它能看什么

| 维度 | 回答的问题 |
|---|---|
| 按域名 | "我的流量都被哪些网站吃了？"（你 300G 的精确去向） |
| 按节点 | "哪个节点用得最多？" |
| 按规则 | "哪条规则放走的流量最多？"（针对性改规则的依据） |
| 按 IP / 代理 | 裸 IP 流量、代理与直连占比 |

数据保留：**分钟级明细 30 天 + 每日汇总长期保留**，正好对应你的月度流量周期。面板实时刷新。

## 走势图点击联动（本机定制功能，官方版没有）

- **点击走势图上任意数据点**：下方的设备/主机/代理/规则四张表立即切换为该时间桶的用量排行
  - 天视图（今天/1天/3天）→ 每个点是**1 小时**，点谁看谁那一小时的排行
  - 周/月视图（7天/15天/30天）→ 每个点是**1 天**，点谁看谁那一天的排行
- **还原**：点击走势图空白处、再点一次同一个点、或点顶部紫色"已筛选 xx ~ xx ✕"徽标，任意一种都恢复全范围
- 顶部新增**「粒度」**下拉框（自动/1分钟/5分钟/1小时/1天），不想用自动映射时可手动指定
- 自动粒度规则：范围 ≤6 小时→5分钟桶；≤3 天→小时桶；更大→天桶

### 深色模式（本机定制）

- 工具栏 **🌙/☀️ 按钮**一键切换深浅色，走势图画布配色同步切换
- 首次打开跟随系统深浅色偏好，手动选择后记住（存在浏览器本地）

## 它是怎么工作的

- 每 2 秒轮询一次 mihomo 内核的 `/connections` 接口（地址 `127.0.0.1:9097`），把每条连接的增量流量按维度聚合写入 SQLite（`C:\Program Files\Clash Verge\traffic-monitor\data\traffic_monitor.db`）
- 长连接（下载模型/视频/更新）计量精确；秒开秒关的极短连接可能只进总量不进域名明细

## 自启动机制

开机登录后，`启动文件夹`里的 `start-traffic-monitor.vbs` 会**延迟 20 秒**（等 Clash 先起来）自动拉起监控，托盘常驻。手动启动也双击这个文件即可：

`C:\Users\xjj20\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\start-traffic-monitor.vbs`

## 日常注意

1. **Clash Verge 的「外部控制器」必须保持开启**（本次已在设置里打开）。如果哪天面板域名列表不走了，九成是它被关了：Verge 设置 → 外部控制器 → 开启
2. 退出监控：托盘图标右键退出；临时停用自启：删除上面那个 .vbs
3. 清空历史数据：删除 `data\traffic_monitor.db` 后重启监控
4. 完整卸载：删 .vbs、托盘退出、删除 `C:\Program Files\Clash Verge\traffic-monitor\` 文件夹、在 Verge 设置里关掉外部控制器（可选）

## 建议的验证步骤（明早）

1. 浏览器开 http://127.0.0.1:18080
2. 随便看几个视频/下载点东西
3. 面板按域名排序——下载量应该出现在对应域名上；走代理的流量 = 消耗你 300G 的流量

## 配合之前的分析使用

看到异常大户后，对照《白羊座规则分析报告.md》：国内站/更新站误走代理 → 用 Merge 前置规则钉直连；HuggingFace 模型下载 → 走 hf-mirror 镜像直连；Telegram/被墙站 → 无解，只能换免流机场。
